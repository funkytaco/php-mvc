composer nimbus:install

Takes an app instance that nimbus:create generated and prepares it to run: copies its assets into place and writes the compose file that nimbus:up needs.

composer nimbus:install [<app>]

Where it sits in the lifecycle

  1. Template The shared blueprint in .installer/_templates/<template>/ — the source of truth you edit.
  2. Create the app instance composer nimbus:create my-app lkui copies the template into .installer/apps/my-app/ and resolves its placeholders.
  3. Install composer nimbus:install my-app copies the instance's assets to the runtime location and generates my-app-compose.yml.
  4. Start the containers composer nimbus:up my-app hands the compose file to podman-compose.

Running it

▸ With an app name

Installs that app directly, no prompting.

composer nimbus:install my-app
App 'my-app' installed successfully!
Container config generated: my-app-compose.yml

▸ Without an app name

Lists every app it knows about and asks which one to install.

composer nimbus:install
Select app to install:
  [1] my-app
  [2] another-app
>

What the command does

  1. Resolve which app Uses the first CLI argument if given; otherwise lists the known apps and prompts. With no apps at all, it stops here with an error.
  2. Copy the app's assets into place Walks the assets map in app.nimbus.json and copies each source into its target.
  3. Write the compose file Generates <app>-compose.yml from the app's declared features and containers.
  4. Report the result Prints a success line naming the generated compose file, or the failure reason.
Verify before relying on the details Steps 2 and 3 summarise AppManager::install() and buildComposeConfig(), which this page has not been checked against. The command entry point is src/Nimbus/Tasks/InstallTask.php; trust the source over this page.

The asset map

Each app's app.nimbus.json declares an assets object mapping source paths inside the app instance to their targets. Install walks that map — it does not copy the instance directory wholesale. 

{
  "assets": {
    "Controllers": "app/Controllers",
    "Views": "app/Views",
    "Models": "app/Models",
    "routes/CustomRoutes.php": "app/CustomRoutes.php",
    "app.config.php": "app/app.config.php"
  }
}
Illustrative, not verbatim The exact keys differ per template. Read the assets block in the template you are actually using — .installer/_templates/<template>/app.nimbus.json.

Errors you will hit

No apps found

[ERROR] No apps found. Create one first with: composer nimbus:create

Nothing exists under .installer/apps/ yet. Create an app first:

composer nimbus:create my-app

Install failed

[ERROR] Failed to install app: <reason>

The message carries the underlying exception. Common causes:

  • The named app does not exist under .installer/apps/
  • app.nimbus.json is missing or is not valid JSON
  • A path in the assets map points at something that isn't there
  • The target directory is not writable

Run composer nimbus:lint-check <template> to catch asset-map problems at the template level.

After a successful install

  1. Start itcomposer nimbus:up my-app
  2. Check it came upcomposer nimbus:status shows container state and health.
  3. Open itThe port is derived from the app name — read it from my-app-compose.yml or from nimbus:status.
Re-running is fine Install is repeatable. After changing app.nimbus.json or adding a feature with nimbus:add-eda / nimbus:add-keycloak, run it again to regenerate the compose file.
Don't edit the generated files app/ and <app>-compose.yml are both generated and gitignored. The next install overwrites them. Edit the template instead — or use nimbus:dev, which serves the app's own instance directory so your edits survive.

Related commands

nimbus:create

Scaffolds a new app instance from a template. Must run before install.

nimbus:up / nimbus:down

Starts and stops an installed app's containers via podman-compose.

nimbus:list
